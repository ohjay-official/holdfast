## The one that matters most

**With no guardian, a robber who has the phone and forces out the home code can empty the vault in about 1 hour, not "a full freeze and the normal wait".**

- With no guardian, the app sets `guardianPk = homePk` and `fastBlocks = 6` (`src/real/main.ts:1205-1211`).
- `approveFast` only checks `checkSig(guardianSig, guardianPk)` (`contracts/Holdfast.cash:288-299`), so the home key passes as the guardian.
- The path is: the phone runs `startWithdrawal` for nearly the whole vault, the home key runs `approveFast`, then anyone runs `releaseFast` after 6 blocks. No freeze is needed.
- I proved it with a scratch test, `/tmp/judge3b/scratch/test/zz-judge.test.ts`, using the repo's own builders. It passes: the robber gets more than 990,000 of 1,000,000 sats, and the same release with 5 blocks is refused.
- The app's UI hides the fast lane when there is no guardian, but the contract does not.
- Better fix: change the contract, e.g. add `require(guardianPk != homePk);` to `approveFast`. That is a contract version 3, and after it the v2 claims below become true.
- Until then, the six rows marked F1 below need the wording fix.
